# 散乱工作区规范化迁移

[English](README.md) | [简体中文](README.zh-CN.md)

> 把散落在临时工作区里的脚本、中间数据和记录文档，规范化迁进一个独立项目，并批量改写脚本里的旧路径，迁完还能跑。

## 这是什么

这不是一次文件搬家。搬文件本身没什么难度，麻烦的是搬完之后脚本里那些写死的路径全断了。

这里把"搬迁"和"改路径"当成一件事做，只有这样才能得到一个能用的结果，而不只是一个整齐的结果。

## 为什么开源

临时工作目录是会攒的：几个脚本、一些中间 json、一份记录文档。到某个时候其中某一个被判断为值得留下，而它躺在一个以日期命名的文件夹里。

每当一个一次性的工作流够格升成正式项目，就走一次这个流程。它是一套整理逻辑，没有专有内容。

## 能做什么

- **先问两件事。** 项目建在哪，以及原来的资产怎么处置 —— 复制归档、移动只留一份、还是只建索引。这两处靠猜，做出来的结果比原样还乱。
- **改路径是一等步骤。** 扫描脚本里的绝对路径并改写到新位置，让它们在新家直接能跑，不用手工改。
- **一份根部索引文档。** 说明每一块是什么，不用把每个文件都打开就能找到东西。
- **可回滚。** 操作过程记录得够细，出问题能退回去。

## 环境要求

Python 3（也可以纯手工做）

## 安装

```bash
git clone https://github.com/<你的用户名>/workbuddy-project-migration.git
```

然后把整个目录放进技能目录：

| 系统 | 路径 |
|---|---|
| Windows | `C:\Users\<你>\.workbuddy\skills\workbuddy-project-migration\` |
| macOS / Linux | `~/.workbuddy/skills/workbuddy-project-migration/` |

没有构建步骤，重启对话即生效。

## 怎么用

直接说要收拢：

- "把这些整理成一个正式项目"
- "只留一份，做成一个项目"
- "把路径改对，让脚本还能跑"

它会先问那两个口径问题，然后一次完成搬迁和改写。

## 文件结构

```
└── SKILL.md
```

## 注意与边界

1. **改路径是按模式匹配的。** 运行时才拼出来的路径有可能漏掉。迁完把脚本跑一次确认。
2. **移动不保留副本是不可逆的。** 这个选项留着，是因为它能避免同一份内容有两个源头；但选它的时候要清楚代价。
3. **临时文件不该跟着迁。** 中间产物一般不该跟着脚本进新项目，索引里写明它原来在哪就行。
4. **git 历史不会跟着走。** 如果原目录是个仓库，搬迁不会自动把历史带过去，除非特意处理。
